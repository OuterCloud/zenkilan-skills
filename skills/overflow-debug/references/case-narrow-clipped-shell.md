# 案例：后台列表页窄屏显示不全（2026-11）

一个「表格在窄屏下显示不全」的反馈，被连续误判四轮，第五轮实测才定位到真因。
本案例是 `overflow-debug` 这个 skill 的全部素材来源。

> 已脱敏：平台名、业务标识、代码路径与仓库提交信息均已去掉，只保留与排查方法相关的结构。

## 用户反馈的演进

| 轮次 | 用户原话 | 当时的猜测 | 实际改动 |
|------|----------|-----------|----------|
| 1 | 列表视觉拥挤，两列挨太近 | 列间距不够 | `column-gap: 16px → 24px` |
| 2 | 名称那一列被挤得太窄 | 列宽分配不合理 | 表单宽度 720 → 1000px，名称列 `minmax(200px,1fr)` |
| 3 | 窄屏下显示不全，不能左右滚动 | 表格缺滚动容器 | 加 `overflow-x-auto`、`minWidth: 700` |
| 4 | 还是不能左右滚 | flex 子项 `min-width:auto` 撑开 | 把 flex 居中改成块级 `mx-auto` |
| 5 | 还是不能滚 | —（终于去量 DOM） | 见下 |

前四轮的猜测各自看起来都很有道理，改动也都能在宽视口下「看起来变好一点」，
所以每一轮都以为自己修好了。**这就是没有实测支撑时最典型的失败模式：改动有效果，但效果和问题无关。**

## 真因

应用外壳组件上同时写了两件事：

```tsx
// 布局外壳（App 层，所有页面共用）
<Layout className="flex-1 min-w-225 overflow-hidden">
```

- `min-w-225` 在 Tailwind 里是 **900px 硬下限**，是历史提交为修另一个宽屏布局问题加的，
  此后一直没人动。
- 它的祖先容器是 `overflow: hidden`。

两者组合的结果：**视口窄于 900px 时，整个应用被裁在视口外，页面里根本不存在能横向滚动的滚动容器。**
内层表格上写多少 `overflow-x-auto` 都不会生效——那个容器本身已经被裁到屏幕外了。

## 700px 视口下的实测数据

改动前：

```
shell      client=700  scroll=900  overflow-x=hidden   ← 裁切点，200px 永远看不到
layout     w=900       min-width=900px
content    clientWidth=788                             ← 整块在视口外
表格 wrap  client=536  scroll=712   canScroll=true      ← 表格自己其实能滚 176px
```

注意最后一行：**表格自身的滚动能力一直是好的**。问题从来不在表格，而在它的祖先。
这解释了为什么前四轮改表格层面的东西全部无效。

改动后（`min-w-225` → `min-w-0`）：

```
shell      client=700  scroll=700                       ← 不再裁切
表格 wrap  client=586  scroll=712   canScroll=true       ← 可滚 126px，交给用户
```

## 修复

```tsx
// 改前
<Layout className="flex-1 min-w-225 overflow-hidden">

// 改后
<Layout className="flex-1 min-w-0 overflow-hidden">
```

`min-w-0` 不是「随便兜个底」，它是有确切含义的：**允许这一层被压到比内容窄，
把「最小宽度」这件事交给真正需要它的内层滚动容器。**
代码注释里写清了这一点，也写清了 900px 是历史遗留，避免下一个人又加回去。

## 连带坑：分组行不跟随表格宽度

列表按分组展示，分组那条横条不在 grid 内，没有继承表格的 `minWidth: 700`。
表格修好能滚之后，横向滚动时右侧出现留白，横条没铺满。

修法：把宽度提成常量，两边共用。

```ts
const GRID_MIN_WIDTH = 700   // 表格与分组行共用
```

中途还试过给分组行加 `sticky left-0`，结果表头文字被滚出视野、横条看着像空的，已回退。
**教训：只有真正在同一个滚动容器里的元素才需要 sticky；分组行只需要对齐宽度。**

## 如果一开始就量

第一次反馈「显示不全」时跑一次：

```bash
node scripts/overflow-probe.mjs <url> --viewport 700x900
```

一条输出：

```
❌ 被裁  溢出 200px  div.shell
        overflow-x=hidden min-width=0px display=flex
```

看到 `div.shell` 和 `overflow-x=hidden`，5 分钟内就能定位到外壳组件。
省掉四个无效的提交，以及至少两轮来回确认。

## 结论

- **症状描述和根因不在同一层**：用户说的是「表格看不到」，根因在页面的外壳。
  靠读表格代码永远找不到。
- **「改完看起来好一点」不等于修好**：调列间距确实让视觉松了一点，但那和「被裁掉 200px」毫无关系。
- **窄屏问题必须用窄视口量**：默认 1440 宽下 `min-width: 900` 永远不会暴露。
